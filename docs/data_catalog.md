# Data Catalog: Gold Layer

This page describes every table, view and column in the Gold layer, which is the layer used for reports.

The Gold layer is a **star schema**: one fact table (`fact_sales`) in the middle, linked to dimension tables for customers, products and dates. Its tables keep history. The views on top of them give a simple "current" picture for analysis.

| Object | Type | One row for each... |
|---|---|---|
| `gold.dim_customers` | Table (SCD Type 1 and 2) | Customer **version** |
| `gold.dim_products` | Table (SCD Type 1) | Product number |
| `gold.dim_date` | Table | Calendar day |
| `gold.fact_sales` | Table | Order line (order number + product number) |
| `gold.vw_dim_customers` | View | Customer (latest version only) |
| `gold.vw_dim_products` | View | Product (all products) |
| `gold.vw_fact_sales` | View | Active sale, linked to the customer's latest version ("as it is") |
| `gold.vw_fact_sales_history` | View | Active sale, linked to the customer version at the time of the sale ("as it was") |
| `gold.vw_sales_analysis` | View | Sale with all customer, product and date details in one row |
| `gold.vw_kpi_summary`, `gold.vw_kpi_by_year` | Views | Business KPIs (created by `scripts/analytics/17_business_kpis.sql`) |

Every dimension has an **Unknown member**: a row with key `-1` that sales link to when their customer, product or date is not known yet.

A **surrogate key** is an ID generated by the warehouse. A **business key** is the ID from the source system.

---

## gold.dim_customers

| Column | Type | Description |
|---|---|---|
| customer_key | INT | Surrogate key. Each version of a customer gets its own key. -1 = Unknown |
| customer_id | INT | Customer ID from the CRM (business key) |
| customer_number | NVARCHAR(50) | Customer number from the CRM, for example AW00011000 (Type 1) |
| first_name | NVARCHAR(50) | First name (Type 1) |
| last_name | NVARCHAR(50) | Last name (Type 1) |
| country | NVARCHAR(50) | Country where the customer lives, for example Australia (**Type 2**: history kept) |
| marital_status | NVARCHAR(50) | Single / Married / n/a (**Type 2**: history kept) |
| gender | NVARCHAR(50) | Male / Female / n/a. Taken from the CRM; the ERP is used if the CRM has no value (Type 1) |
| birthdate | DATE | Date of birth. Dates in the future are removed (Type 1) |
| create_date | DATE | Date the customer was created in the CRM (Type 1) |
| effective_date | DATETIME2(3) | When this version starts (included). The first version starts on 1900-01-01 |
| expiry_date | DATETIME2(3) | When this version ends (not included). NULL = still valid |
| is_current | BIT | 1 = this is the current version (at most one per customer) |
| is_deleted | BIT | 1 = the customer was deleted in the source |
| scd1_hash, scd2_hash | VARBINARY(32) | Hashes used to find Type 1 and Type 2 changes |
| dwh_batch_id, dwh_insert_date, dwh_update_date | | Which run loaded the row, and when it was added and last updated |

## gold.dim_products

| Column | Type | Description |
|---|---|---|
| product_key | INT | Surrogate key. -1 = Unknown |
| product_id | INT | CRM ID of the current version of the product |
| product_number | NVARCHAR(50) | Product number, for example BK-R93R-62 (business key) |
| product_name | NVARCHAR(50) | Product name, including colour and size |
| category_id | NVARCHAR(50) | Category ID, for example BI_RB |
| category | NVARCHAR(50) | For example Bikes, Components |
| subcategory | NVARCHAR(50) | For example Road Bikes |
| maintenance | NVARCHAR(50) | Yes / No |
| cost | INT | Cost of the product |
| product_line | NVARCHAR(50) | Mountain / Road / Touring / Other Sales / n/a |
| start_date | DATE | Start date of the current version of the product |
| is_active | BIT | 0 = the product no longer has a current version |
| scd1_hash, dwh_* | | Hash used to find changes, and load details |

## gold.dim_date

| Column | Type | Description |
|---|---|---|
| date_key | INT | The date as a number, YYYYMMDD. -1 = Unknown |
| full_date | DATE | The calendar date |
| year_number, quarter_number, month_number | | Year, quarter and month |
| month_name, day_name | NVARCHAR(20) | Names of the month and day (in the server's language) |
| year_month | CHAR(7) | For example 2013-05 |
| day_of_month, day_of_week | TINYINT | Day of the month, and day of the week (1 = Monday) |
| week_of_year | TINYINT | Week number (ISO standard) |
| is_weekend | BIT | 1 = Saturday or Sunday |

## gold.fact_sales

| Column | Type | Description |
|---|---|---|
| sales_key | BIGINT | Surrogate key |
| order_number | NVARCHAR(50) | Sales order number, for example SO43697 |
| product_number | NVARCHAR(50) | Business key of the product. Kept so late-arriving products can be linked later |
| customer_id | INT | Business key of the customer. Kept so late-arriving customers can be linked later |
| product_key | INT | Link to `dim_products` |
| customer_key | INT | Link to `dim_customers`: the customer version that was valid on the order date |
| order_date_key, shipping_date_key, due_date_key | INT | Links to `dim_date` |
| order_date, shipping_date, due_date | DATE | The dates (NULL if the date in the source was invalid) |
| sales_amount | INT | Revenue for the line = quantity × price |
| quantity | INT | Number of units ordered |
| price | INT | Price of one unit |
| is_deleted | BIT | 1 = the line was deleted or cancelled in the source. The views leave these out |
| dwh_batch_id, dwh_insert_date, dwh_update_date | | Which run loaded the row, and when it was added and last updated |
