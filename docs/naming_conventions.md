## General Rules

- **snake_case:** use lowercase letters, with underscores (`_`) between words.
- **English:** all names are in English.
- **No reserved words:** do not use SQL keywords (like `table` or `order`) as names.

## Table Names

### Bronze

- Start with the source system name, and keep the original table name. Do not rename it.
- Pattern: **`<sourcesystem>_<entity>`**
  - `<sourcesystem>`: the source system, for example `crm` or `erp`.
  - `<entity>`: the exact table name from the source system.
  - Example: `crm_cust_info` = customer information from the CRM.

### Silver

- Same rule as Bronze: start with the source system name, and keep the original table name.
- Pattern: **`<sourcesystem>_<entity>`**
  - `<sourcesystem>`: the source system, for example `crm` or `erp`.
  - `<entity>`: the exact table name from the source system.
  - Example: `crm_cust_info` = customer information from the CRM.

### Gold

- Use clear business names, starting with a prefix that shows the table's role.
- Pattern: **`<category>_<entity>`**
  - `<category>`: the role of the table, for example `dim` (dimension) or `fact` (fact table).
  - `<entity>`: a business name, for example `customers`, `products` or `sales`.
  - Examples:
    - `dim_customers` = dimension table with customer data.
    - `fact_sales` = fact table with sales transactions.

**Prefixes**

| Prefix | Meaning | Examples |
|---|---|---|
| `dim_` | Dimension table | `dim_customers`, `dim_products` |
| `fact_` | Fact table | `fact_sales` |
| `report_` | Report view | `report_customers`, `report_products` |

## Column Names

### Surrogate Keys

A **surrogate key** is an ID generated by the warehouse.

- The main key of every dimension table ends with `_key`.
- Pattern: **`<table_name>_key`**
  - `<table_name>`: the table or thing the key belongs to.
  - `_key`: shows that this is a surrogate key.
  - Example: `customer_key` = the surrogate key in `dim_customers`.

### Technical Columns

Technical columns are columns added by the system, not by the source.

- They start with `dwh_`, followed by a name that explains what they hold.
- Pattern: **`dwh_<column_name>`**
  - `dwh`: used only for columns created by the system.
  - `<column_name>`: what the column is for.
  - Example: `dwh_create_date` = when the row was first loaded.

## Stored Procedures

- Procedures start with `usp_`, followed by a verb that says what they do.
- Pattern: **`<schema>.usp_<verb>_<object>`**
  - Examples:
    - `bronze.usp_extract_table`: copies one source table into Bronze.
    - `silver.usp_load_crm_cust_info`: cleans and loads one Silver table.
    - `gold.usp_load_dim_customers`: loads one Gold dimension.
    - `etl.usp_run_pipeline`: the main pipeline.
- Procedures that run the framework are in the `etl` schema. Logging helpers are in the `audit` schema.
- `gold.load_gold` is named after the layer, because it runs all the Gold loads in order.
